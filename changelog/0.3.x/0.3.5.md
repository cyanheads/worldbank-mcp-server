# 0.3.5 — 2026-09-12

## Added

- **`ppp_version`** on `worldbank_get_poverty` selects a PPP vintage (`"2021"`, `"2017"`) from PIP's current data release; the resolved vintage and release are echoed as `appliedFilters.pppVersion`/`appliedFilters.releaseVersion`, and an unsupported vintage is rejected as `ppp_version_unavailable` naming the vintages that exist (#35).
- **`surveyComparability` and `comparableSpell`** on `worldbank_get_poverty` rows report PIP's series-comparability code and covered year span, `null` on gap-filled rows (#35).
- **Page-past-end notices** on `worldbank_get_data`, `worldbank_get_poverty`, `worldbank_search_projects`, `worldbank_list_countries`, and `worldbank_list_sources` name the page range that actually exists once a request runs off the end (#30).

## Changed

- **`worldbank_search_projects` and `worldbank_get_poverty` cap rows per page** — 80 projects (8 with `include_abstract`) and 70 estimates, keeping each response under ~50 KB. A larger `per_page`, including the server default, is silently reduced; the reduction is disclosed in `notice` and echoed as `appliedFilters.perPage`/`requestedPerPage`, with `totalPages` counted at the served size (#31).
- **A reversed `date_range` or `"all"` mixed with country codes on `worldbank_get_data`, and a non-ISO2 country code on `worldbank_search_projects`, now reject as typed errors** (`reversed_date_range`/`mixed_all_selector`/`invalid_country_code`) with a `recovery` hint, instead of a bare schema validation message.

## Fixed

- **`worldbank_get_data` keeps date-filtered `totalCount`/`totalPages` invariant across pages** — a windowed query re-reads the full series whenever the page in hand isn't already the whole series, rather than trusting upstream's raw per-page pagination on an exhausted page (#30).
- **`worldbank_search_projects` rejects a non-calendar date** (e.g. `2023-02-29`) **and a reversed `approved_from`/`approved_to` window**, instead of forwarding the date to the Projects API — which crashes on an out-of-range month — or silently returning zero matches on a reversed window (#32).
