# 0.3.6 — 2026-09-12

## Added

- **`dimension_value`** on `worldbank_get_data` selects a source-scoped dataset's extra dimension by id — a WDI release, an ICP/FPN classification, a GDLD sector, or an IDS counterpart area — matched case-insensitively; an unknown id is rejected with the valid ones ([#27](https://github.com/cyanheads/worldbank-mcp-server/issues/27)).
- **`sourceScoped`** on the response discloses the serving source id/name, the dimension concept/selection/id/label applied, and a note that the values are not from the standard data endpoint and may be archived or superseded; each row carries its own `dimension` too ([#27](https://github.com/cyanheads/worldbank-mcp-server/issues/27)).
- **`unknown_dimension_value`, `dimension_not_applicable`, `source_scope_too_large`** typed error reasons on `worldbank_get_data` cover an invalid dimension id, a dimension_value given where none applies, and a source-scoped query too large for one request (countries × periods × unpinned dimension values) ([#27](https://github.com/cyanheads/worldbank-mcp-server/issues/27)).

## Changed

- **`indicator_not_queryable` narrows to indicators no catalog source can serve at all** — an id the standard endpoint rejects now routes to its source's source-scoped data API instead of failing outright ([#27](https://github.com/cyanheads/worldbank-mcp-server/issues/27)).
