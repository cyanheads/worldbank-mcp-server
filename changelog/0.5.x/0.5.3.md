# 0.5.3 — 2026-10-07

## Added

- **`.env.example` and README** document the opt-in `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` (OTLP log export) and `LOG_TOOL_FAILURE_PAYLOADS` / `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES` (failed-call payload logging), both added in framework 0.13.8 (cyanheads/mcp-ts-core#547, cyanheads/mcp-ts-core#291). `.env.example` also lists the framework's `MCP_REQUEST_STATE_KEY` opt-in.

## Changed

- **Tool error results** close `content[]` text with `request <id>`, and error `data` carries `requestId` (framework 0.13.10, cyanheads/mcp-ts-core#576).
- **Error envelopes** no longer carry `data.rootCause` (0.13.13, cyanheads/mcp-ts-core#644); request context fields no longer reach client error data (0.13.8, cyanheads/mcp-ts-core#548).
- **Argument repair:** a JSON-stringified object or a safe integer sent for a string field is repaired before validation (0.13.9, cyanheads/mcp-ts-core#479, cyanheads/mcp-ts-core#487), and argument-rejection hints name field paths and alias rewrites (0.13.9).
- **Upstream fetch errors** name a URL by origin only (0.13.12, cyanheads/mcp-ts-core#626).
- **`ctx.log` client notifications** honor `MCP_LOG_LEVEL` and mask sensitive fields (0.13.11, cyanheads/mcp-ts-core#621, cyanheads/mcp-ts-core#630); argument-rejection and missing-capability refusals log at `notice` instead of `error` (0.13.10, cyanheads/mcp-ts-core#567).
- **MCP SDK** `@modelcontextprotocol/server` ^2.0.0 → ^2.2.0 via the framework (2.1.0 in 0.13.9, 2.2.0 in 0.13.11). On the 2026-07-28 protocol revision a POST without `MCP-Protocol-Version` is refused `400`/`-32020`, and a JSON-RPC batch over 100 messages is refused (0.13.9).
- **Tool and resource handlers** drop the explicit `ctx.recoveryFor(...)` forwards: the framework fills each declared `recovery` hint itself (0.13.10, cyanheads/mcp-ts-core#579), and the hint callers receive is unchanged. The forward on `worldbank_get_poverty` `invalid_parameter` stays.
- **`Dockerfile`** installs production dependencies in a `deps` stage pinned to `$BUILDPLATFORM` with cross-install (0.13.10, cyanheads/mcp-ts-core#575), installs OTel peers through `scripts/install-otel.ts` (0.13.10, cyanheads/mcp-ts-core#578), and prunes musl-only native packages (0.13.11, cyanheads/mcp-ts-core#608). The `MCP_FORCE_CONSOLE_LOGGING` default is removed.
- **`server.json`** npm entries use `runtimeHint: "npx"` without the `run start:*` arguments, and the streamable-http entry sets `MCP_TRANSPORT_TYPE` to `http` (0.13.11, cyanheads/mcp-ts-core#622).
- **Ignore files** cover every env file (0.13.11, cyanheads/mcp-ts-core#589); `.mcpbignore` adds `/docs/idea.md`, `/logs/`, and `/.cache/`.
- **CodeQL workflow** runs one job per language (0.13.11, cyanheads/mcp-ts-core#470).
- **Skills and scripts** resynced from the framework; the `test` script calls `vitest` directly.
