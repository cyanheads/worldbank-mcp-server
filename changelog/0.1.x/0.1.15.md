# 0.1.15 — 2026-08-09

## Added

- **`WORLDBANK_CATALOG_CACHE_TTL_MS`** env var — lifetime in ms of the in-process indicator-catalog cache backing keyword-only search. Default `3600000`; `0` disables caching and refetches on every search.

## Changed

- **Keyword matching** is now token-AND over alphanumeric terms (query and indicator text are lowercased and split on punctuation, not whitespace), ranked exact ID/name match first, then whole-phrase match, then remaining ID/name matches, then description-only matches. `gdp per capita` and `per capita GDP` now return the same 108 hits instead of 38 and 8.
- **Maintenance tooling** — re-synced framework `scripts/` and `skills/` to `@cyanheads/mcp-ts-core` `^0.11.1`: Socket security scanner wired into `bunfig.toml`/`devcheck.config.json`, a `minimumReleaseAge` supply-chain guard (`@cyanheads/mcp-ts-core` excluded for same-day framework adoption), a BuildKit cache mount and pinned `oven/bun:1.3.14` base in `Dockerfile`, an `overrides` section added to `scripts/check-dependency-specifiers.ts`'s floating-specifier check, and new `.gitattributes` / `.github/FUNDING.yml` / `.github/SECURITY.md`.

## Fixed

- **`worldbank_search_indicators`** keyword-only search now matches locally against an exhaustively fetched, TTL-cached indicator catalog instead of relying on the upstream `searchterm` parameter, which does not filter — `?searchterm=zzzz-no-such-indicator-xyz` returns the full catalog with `total: 29544`. [#16](https://github.com/cyanheads/worldbank-mcp-server/issues/16)
- Combined **keyword + `topic_id`/`source_id`** searches now fetch every upstream page for the selected scope before matching, replacing a fixed `page=1&per_page=1000` request that dropped matches past the first page (topic 4 alone holds 1,014 indicators, source 2 holds 1,498). [#14](https://github.com/cyanheads/worldbank-mcp-server/issues/14)
- Invalid **`topic_id`/`source_id`** values now throw a declared `invalid_filter` error with a recovery hint instead of surfacing an internal output-schema validation error; the unreachable `no_match` contract entry was removed since an empty result was already returning structured success. [#15](https://github.com/cyanheads/worldbank-mcp-server/issues/15)
- **`worldbank_list_countries`** with `include_aggregates=false` now fetches every upstream page instead of capping at a fixed 300-entity request, so `totalCount`/`totalPages` no longer under-report once the entity count crosses that ceiling. [#21](https://github.com/cyanheads/worldbank-mcp-server/issues/21)
