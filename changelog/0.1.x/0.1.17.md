# 0.1.17 — 2026-08-09

## Added

- **`appliedFilters`** enrichment field on `worldbank_get_data` (`indicatorId`, `countries`, optional `dateRange`/`mrv`, `page`, `perPage`) and `worldbank_search_indicators` (optional `query`, `topicId`, `sourceId`) — echoes the effective parameters sent upstream, rendered as a labelled `**Applied Filters:**` line in `content[]` and mirrored to `structuredContent`. [#12](https://github.com/cyanheads/worldbank-mcp-server/issues/12)
- **`errors`** contract on `worldbank://country/{countryCode}` and `worldbank://indicator/{indicatorId}` — a genuine not-found now carries `data.reason` (`country_not_found`/`indicator_not_found`) and a recovery hint pointing at `worldbank_list_countries`/`worldbank_search_indicators`, matching the equivalent tools. [#19](https://github.com/cyanheads/worldbank-mcp-server/issues/19)

## Fixed

- **Resource handlers** for country and indicator no longer relabel a network failure, timeout, or 5xx as a definitive not-found — only a genuine upstream miss maps to `NotFound`; every other rejection propagates with its own classification so a client retries instead of concluding the entity doesn't exist. [#19](https://github.com/cyanheads/worldbank-mcp-server/issues/19)
- **`worldbank_search_indicators`** no longer returns the same indicator ID twice or double-counts it in `totalCount`. The exhaustively fetched candidate pool carried 43 IDs published under both a live source and an archived copy, plus 11 page-boundary repeats from `/indicator`'s unstable row ordering; both collapse to one row per ID before ranking, preferring the non-archived source and, when neither is archived, the lower source ID. `worldbank_get_indicator` and `worldbank://indicator/{indicatorId}` apply the same tie-break, so a duplicate ID no longer reports a different source depending on which path resolved it. [#23](https://github.com/cyanheads/worldbank-mcp-server/issues/23)
